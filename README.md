# 实时手势交互训练系统

## 项目简介

基于前后端分离架构的实时手势交互训练系统。

用户在浏览器上传图像或开启摄像头，前端按固定频率抽帧并以 Base64 上传；后端调用 MediaPipe HandLandmarker 提取 21 个手部关键点，换算成 42 维特征（含镜像归一化）后交给 SVC 分类器判定手势——**14 类**，不含「其他」时时间切分准确率 **96.9%**；判不准、四不像的输入统一兜进「其他」，不强行给出真手势。

## 技术栈

*   **前端**：原生 HTML5 + JavaScript（后续计划升级为 Vue3 + Element Plus）
*   **后端**：Python 3.12.8, FastAPI, Uvicorn
*   **数据校验**：Pydantic
*   **AI 引擎**：MediaPipe 1.2.3（Tasks API · HandLandmarker）, OpenCV 5.1, NumPy 2.5
*   **分类器**：scikit-learn 1.9（SVC · RBF 核 · probability=True）

> 全仓库共用一个 `.venv`（`E:\motrack\.venv`），后端与 `gesture/` 工具链依赖同一套环境。

> mediapipe / numpy / opencv 三者版本互相耦合，改动前请参考 `requirements.txt` 中的注释。

## 接口

两条通道，返回结构一致（WS 版多 `type` 和 `ts` 两个字段），前端用 `USE_WS` 开关切换。

| 通道 | 地址 | 上行 | 说明 |
|---|---|---|---|
| HTTP | `POST /api/Gestureinput` | `{"img_64": "data:image/jpeg;base64,..."}` | 单帧、无状态，保留作回退路径 |
| WebSocket | `WS /ws/gesture` | **二进制帧**（JPEG 字节，不套 JSON） | 长连接，每连接一份投票历史 |
| 指标 | `GET /api/stats` | — | 连接数、帧数、丢帧、p50/p95 延迟、FPS |

`/api/stats` 返回示例：

```json
{"connections":0,"connections_peak":1,"frames_in":20,"frames_served":20,
 "frames_dropped":0,"errors":0,
 "latency_ms":{"p50":18.0,"p95":44.0,"max":44.0},
 "fps":10.0,"uptime_s":20.5}
```

`latency_ms` 是**服务端处理耗时**（解码 + 检测 + 分类），不含网络往返。

WS 的三条约定：

- **一帧一应答**：客户端收到结果才发下一帧，天然背压
- **服务端丢旧帧**：处理慢时缓冲区只留最新一张，不排队堆积
- **坏数据回错误帧**：`{"type":"error","code":"decode_failed"}`，不断连接

每条连接持有自己的 **VIDEO 模式检测器**（跨帧追踪），单帧约 **28ms**；
HTTP 走共享的 IMAGE 检测器，同图约 45–56ms。检测器上限 4 个，超出或创建失败时
自动退回共享检测器，连接不受影响。

心跳：客户端发文本帧 `ping`，服务端回 `{"type":"pong"}`。

> WS 逻辑全在 `backend/ws_gesture.py`，`main.py` 只多两行 `include_router`。
> 想退回纯 HTTP，注释掉那两行即可。

## 手势判定

> **2026-11-25 更新**：判定已改为「21 点特征 + SVC 分类器」，14 类；下文的关节角度规则是历史方案，保留作对照。
> 特征定义、采集与训练流程见 [`gesture/README.md`](gesture/README.md)。

**当前流程**：

```
21 点 → extract() 得 42 维（像素归一化 + 掌长门控 + 旋转对齐 + 可选镜像）
      → SVC predict_proba
      → 置信度 < 0.60 或 top1−top2 < 0.15  →  归「其他」
      → 5 帧多数票平滑（不足 3 票也归「其他」）
```

**镜像归一化**：训练集只有一只手，另一只手做同样动作在画面里是镜像关系，取反 x 即可对齐。
是否镜像由 MediaPipe 的 handedness 决定；分数低于 0.80 时只"不镜像"，不丢帧——
模型做过镜像增广，对翻不翻不敏感。

**「其他」是出口不是类别**：它吸收了"不是任何目标手势"的输入。没有它，模型对任何输入都必须硬选一个真手势
（比个大拇指会被判成中指）。代价是它自己的召回很低（约 19%），这部分靠门控和投票兜。

**历史方案（角度法）**：

**关键点**：MediaPipe HandLandmarker 输出 21 个手部关键点，索引顺序固定（0 手腕，1–4 拇指，5–8 食指，9–12 中指，13–16 无名指，17–20 小指）。

**判据**：以 PIP 关节为顶点，计算 `MCP → PIP → TIP` 三点夹角。

| 部位 | 顶点 | 伸直判定 |
|---|---|---|
| 四指 | PIP | θ ≥ 165° |
| 拇指 | IP | θ ≥ 155° |

**坐标系**：所有角度在像素坐标下计算（`x·宽`、`y·高`）。MediaPipe 输出为归一化坐标，x/y 按不同比例缩放（1920×1080 下相差 1.78 倍），直接使用会使角度产生系统性偏差。

**质量门控**：

手部尺寸比例 = (手腕 ↔ 中指 MCP 的像素距离) / 画面短边

比例低于 0.18 时不做手势判定，返回 `state = "low_confidence"` 与靠近提示。依据：手部过小时，蜷曲手指的 `PIP → TIP` 向量极短，关键点定位误差会大幅偏转其方向，导致判定失效（实测同姿势由 30.5° 漂移至 140.7°）。

## 产品定位（未实现）

**现在这个是技术验证原型，不是产品。** 它只做到"感知"这一段：

```
感知：画面 → "食指"            ← 已完成
产品：用户意图 → 手势 → 事情办成 → 有反馈   ← 未做
```

中间缺三样：**意图定义**（哪个手势代表什么动作）、**动作状态机**（保持时长 + 冷却，防误触）、**场景**（不用手势就办不成的事）。

如果要做成产品，最小闭环是两周的量：

| 方向 | 形态 | 为什么要它 |
|---|---|---|
| 免接触操作层 | 比手势控制翻页 / 播放暂停，替代键鼠 | 场景清楚，复用度 90% |
| 动作评估器 | 不比"对错"，算"完成度 87%，中指偏 31°" | 数据可复用（每类 400 条即标准姿态分布） |

**当前决定：停在这里，不再往产品推进。** 理由是继续投入换来的是"产品工程"
（账号、部署、多用户），不是"技术判断"；而项目的技术价值——特征设计、评估体系、
增广与阈值实验——已经完整（见 [`gesture/README.md`](gesture/README.md#75-消融实验)）。

## 已知限制

*   手指指向镜头或手掌侧对镜头时，两点投影缩短，判据可能失效
*   拇指判据余量较薄（约 10°），需补充更多负样本
*   门控阈值 0.18 基于 4 张样本估计，待接入摄像头后用真实分布重新标定
*   当前为单图 HTTP 模式，无时序信息，`cooldown` / `success` 等状态尚未启用
*   多手场景未充分验证（左右手标签、双手排序）

**分类器阶段**：

*   14 类（4 单指 + 9 组合 + 其他），5091 条样本；总体 88.5%，**不含「其他」96.9%**
*   「其他」召回只有 19%——它不是一个类而是一个补集，靠门控与投票兜底，无法单独训好
*   数据来自单人、单机、两个时段录制，跨会话 / 跨光照 / 跨人未验证
*   阈值 `CONF_MIN=0.60` / `MARGIN_MIN=0.15` 在旧数据集上估的，扩类后未重新标定
*   投票状态 `_hist` 是进程内全局变量，多标签页/多用户会互相干扰，上线前需按 session 隔离
*   无名指 / 小指单独伸出在生理上很别扭，采集形态高度一致，真实场景换人后可能不准

## 快速开始

```powershell
cd E:\motrack
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt

cd backend
..\.venv\Scripts\python -m uvicorn main:app --reload --port 8000
```

首次运行会自动下载 `hand_landmarker.task`（约 7.8 MB）。启动后访问 `/docs` 可直接调用接口。

> 必须在 `backend/` 目录下启动，否则要写 `backend.main:app`；`--app-dir backend` 也可以。从仓库根启动 `.venv` 会让 watchfiles 监控整个虚拟环境，启动明显变慢。
